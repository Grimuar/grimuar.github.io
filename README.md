# Gorban Studio

Статический сайт без сборки и внешних зависимостей. Публичная база: https://grimuar.github.io/.

## Локальный просмотр

Из корня репозитория:

```sh
python3 -m http.server 8000
```

Открыть http://localhost:8000/. Используйте HTTP, а не file://: пути рассчитаны на корень домена GitHub Pages.

## Структура

- `index.html` — студия и каталог.
- `projects/gramma-first-words/` и `projects/gramma-words-from-words/` — страница проекта, `privacy.html`, `support.html`.
- `assets/css/base.css` — палитра, типографика; `components.css` — общие компоненты; `pages.css` — раскладка страниц.
- `assets/js/locales/en.js`, `ru.js` — исходные тексты генератора; `localization.js` — совместимость языковых якорей юридических страниц; `main.js` — контакты, меню, резервные изображения и год.
- `ru/` — пять сгенерированных русских страниц; `tools/generate-localized-pages.py` — их генерация и проверка.
- `assets/images/studio/monogram.svg`, `favicon.svg` — временный знак GS.
- `FeatureImage.png`, `favicon.png` — сохранённые исходные изображения First Words.
- `assets/images/gramma-words-from-words/` — PNG-заглушка и резервный SVG.
- Корневые `privacy.html`, `support.html` — совместимость старых адресов.
- `robots.txt`, `sitemap.xml`, `404.html` — индексация и страница ошибки.
- `app-ads.txt` — рекламный файл: не редактировать.

## Изображение Words from Word

Замените **`assets/images/gramma-words-from-words/FeatureImage.png`** настоящим PNG размером **1024 × 500 px** (или пропорциональным изображением). Это общая картинка каталога и страницы игры. После замены PNG обязательно заново создайте `FeatureImage.webp`, чтобы браузеры не продолжали показывать старый вариант. HTML/CSS менять не нужно. При ошибке загрузки JS использует `placeholder.svg`. После замены обновите кеш браузера.

## Добавление проекта и магазинов

Создайте каталог в `projects/`, используя существующую страницу как основу; добавьте карточку на главную, ссылку в подвал и адреса в sitemap. Задайте уникальные title, description, canonical и Open Graph. Создайте отдельные поддержку и политику: не переносите юридические утверждения другого приложения.

Кнопки магазинов находятся в `.store-links` страницы проекта. Добавляйте только подтверждённые URL; не меняйте package ID. Для Words from Word активируйте отключённые кнопки после получения подтверждённых ссылок. Не используйте `href="#"` для магазинов.

## Как редактировать тексты сайта

Основные источники текстов: `assets/js/locales/en.js` и `assets/js/locales/ru.js`. Ключи совпадают; разделы `common`, `studio`, `firstWords`, `wordsFromWords`, `stores` содержат утверждённые переводы. Например, описание второй игры — `wordsFromWords.description`.

После изменения строк запустите из корня репозитория:

```sh
python3 tools/generate-localized-pages.py
python3 tools/generate-localized-pages.py --check
python3 tools/update-assets-version.py --check
python3 -m http.server 8000
```

Откройте http://localhost:8000/ и http://localhost:8000/ru/. Тексты уже находятся в HTML и работают без JavaScript. Русские страницы вручную не редактируйте: генератор перезапишет их. Английские страницы — основа общей разметки; фрагменты с `data-i18n` обновляются из словарей. Меняя общую структуру, редактируйте английскую основу, затем запускайте генератор. `--check` ничего не пишет и возвращает код 1 при устаревших страницах.

Генератор не выполняет JavaScript. Его строгий парсер принимает текущий формат словарей: объекты с ключами-идентификаторами, строками в двойных кавычках, комментариями и завершающими запятыми. Выражения, функции, массивы, повторяющиеся ключи и иной неподдерживаемый синтаксис вызывают ошибку до записи страниц. Не меняйте служебные строки `window.GorbanLocales...`. В строках используйте `\"` для двойных кавычек, апострофы — напрямую, переносы — `\n`. Для `data-i18n-lines` перенос превращается в `<br>`. Остальной текст HTML экранируется.

Добавляя строку, создайте одинаковый ключ в обоих словарях и `data-i18n="раздел.ключ"` на текстовом элементе английской страницы. Не ставьте атрибут на контейнер с интерактивными элементами. Для новой пары страниц дополните список `PAIRS` в генераторе и sitemap. Метаданные RU и доступные подписи формируются генератором; новые специальные подписи добавляйте там. SEO-описания игр задаются отдельно в `tools/seo-metadata.json`; остальные исходные title/description находятся в английских основах и правилах генератора.

### Отдельные языковые URL

| EN | RU |
|---|---|
| `/` | `/ru/` |
| `/projects/gramma-first-words/` | `/ru/projects/gramma-first-words/` |
| `/projects/gramma-words-from-words/` | `/ru/projects/gramma-words-from-words/` |
| `/projects/gramma-first-words/support.html` | `/ru/projects/gramma-first-words/support.html` |
| `/projects/gramma-words-from-words/support.html` | `/ru/projects/gramma-words-from-words/support.html` |

EN/RU — обычные ссылки на соответствующую страницу, с перезагрузкой и без JavaScript. Активный язык отмечен `aria-current="page"`. Старый localStorage больше не читается: язык определяется адресом. Автоматических перенаправлений, History API и перевода DOM нет.

У каждой пары собственные canonical и локализованные метаданные. Взаимные hreflang `en`, `ru`, `x-default` указывают на пару; `x-default` ведёт на EN. В sitemap 14 адресов: исходные 9 и 5 русских. При добавлении страниц обновляйте sitemap вручную, без вымышленных lastmod.

Юридические документы не дублируются в `/ru/` и не переводятся генератором. Он обновляет только их SEO-метаданные в `<head>`, сохраняя содержимое документов. Они содержат RU/EN/中文 на прежних адресах; ссылки из EN ведут на `#en`, из RU — на `#ru`. Их hreflang не добавляется. Содержимое документов редактируется отдельно. `localization.js` оставлен только как совместимость шапок юридических документов: открывает ссылки на существующие языковые якоря, не меняя тексты.

Контакт задан в `siteConfig.contactEmail` в `assets/js/main.js`; сохраняйте соответствующий резервный адрес в исходной английской разметке и юридических документах.

## Перед публикацией

1. Просмотрите все страницы на ширинах 320, 375, 768, 1024, 1440 и 1920 px в EN/RU, с клавиатуры, без JS и с reduced motion.
2. Проверьте переключение/сохранение языка, меню и Escape, фокус, ссылки и консоль.
3. Проверьте `/privacy.html#en`, `/privacy.html#zh`, `/support.html`. JS сохраняет якорь; без JS meta refresh не гарантирует его сохранение, поэтому предусмотрены отдельные ссылки на версии политики.
4. Сверьте юридические документы с фактической реализацией SDK, рекламой, аудиторией и декларациями магазинов; проверьте даты вступления в силу. Документы обеих игр включены в sitemap и доступны для индексации.
5. Добавьте подтверждённые ссылки магазинов Words from Word. Изображения при обновлении документов не менялись.
6. Сверьте `shasum -a 256 app-ads.txt` с `a97573f08f596d0932faafdb008133e2a9a79c493a90b364724654a0db11f731`.
7. Проверьте `git diff --check`, `git diff` и ветку. Работа ведётся в `feature/studio-website`; commit, push, merge и публикация выполняются только по отдельному разрешению.

Сайт не содержит аналитики, трекеров, серверной формы и внешних шрифтов. Системный стек шрифтов поддерживает кириллицу. Настройки GitHub Pages не меняются.

## Юридические документы

У каждой игры есть самостоятельные страницы:

- `projects/gramma-first-words/privacy.html`, `terms.html`, `support.html`.
- `projects/gramma-words-from-words/privacy.html`, `terms.html`, `support.html`.

Политика и условия использования содержат три полных раздела: русский (`id="ru" lang="ru"`), английский (`id="en" lang="en"`) и китайский (`id="zh" lang="zh-Hans"`). Ссылки `#ru`, `#en`, `#zh` прокручивают к разделам без JavaScript. На юридических страницах EN/RU в шапке ведёт к языковым разделам документа; основной сайт использует отдельные EN/RU URL. Общие стили уже задают отступ при переходе к якорю.

Редактируйте юридические тексты прямо в соответствующем HTML. Согласованно обновляйте три языка и обе игры, проверяя название приложения, дату, canonical и ссылки на документы того же проекта. Тексты не входят в общие словари EN/RU: это самостоятельные трёхъязычные документы, которые должны читаться без JavaScript. Проверяйте юридическую терминологию и смысл после перевода. Корневые `privacy.html` и `support.html` остаются прежними перенаправлениями.

## Версионирование CSS и JavaScript

Все локальные CSS и JavaScript, подключаются с общей фиксированной версией из `tools/assets-version.txt` (сейчас `1.0.3`). Новый номер создаёт новые URL ресурсов: браузер не использует для них старые записи кеша. Физические имена файлов и адреса страниц не меняются.

Единственный источник номера — `tools/assets-version.txt`. Скрипт `tools/update-assets-version.py` использует только стандартную библиотеку Python 3. Он обновляет URL подключений во всех HTML проекта, сохраняет другие query-параметры и якоря, не меняет внешние ссылки, изображения, SEO, текст документов и порядок загрузки скриптов.

Из корня репозитория на macOS обновите номер **одной командой**:

```sh
python3 tools/update-assets-version.py --set 1.0.4
```

В дальнейшем используйте `1.0.5` и следующие номера; не переиспользуйте ранее опубликованный номер для изменённых ресурсов. Команда меняет конфигурационный файл и подключения в HTML, выводя список изменённых страниц.

Если номер уже изменён вручную в `tools/assets-version.txt`, примените его:

```sh
python3 tools/update-assets-version.py
```

Проверка без записи файлов:

```sh
python3 tools/update-assets-version.py --check
```

При расхождении команда перечисляет страницы и завершается с кодом 1; при согласованности — с кодом 0. Повторный обычный запуск не меняет уже согласованные файлы и не создаёт повторных `v`.

После изменения загружаемых CSS или JavaScript повышайте общую версию и включайте обновлённые HTML и ресурсы в одну публикацию. Изменения словарей применяются генератором к HTML. При редактировании только юридического HTML повышать версию не требуется: CSS/JS не изменились.

Для локальной проверки:

```sh
python3 tools/update-assets-version.py --check
python3 -m http.server 8000
```

Откройте http://localhost:8000/, проверьте EN/RU и мобильное меню. В DevTools → Network у всех подключённых CSS/JS должен быть одинаковый `v`: на обычной языковой странице это три CSS и один JS; юридические страницы сохраняют прежние четыре JS. После увеличения версии браузер должен запросить новые URL; выбранный язык должен сохраниться.

Ограничение: этот механизм срабатывает после получения обновлённого HTML. Он не гарантирует немедленного обновления уже закешированного HTML. Заголовками кеширования управляет GitHub Pages; `meta http-equiv="Cache-Control"` здесь не используется. Версионирование также не обеспечивает атомарность публикации на сервере: все изменённые ресурсы и HTML следует публиковать вместе.

### Порядок обновления после перехода на статические языковые страницы

При изменении текста словаря запускайте генератор: сам сайт больше не подставляет переводы JavaScript. Для изменения только HTML повышение версии ресурсов не требуется; при изменении реально загружаемых CSS/JS повысьте её:

```sh
python3 tools/update-assets-version.py --set 1.0.4
python3 tools/generate-localized-pages.py
python3 tools/generate-localized-pages.py --check
python3 tools/update-assets-version.py --check
```

Маркетинговые страницы загружают только `main.js`; словари используются локальным генератором. Юридические страницы сохраняют прежние подключения ради неизменности их разметки, все с общей версией. Генератор применяет текущую версию к новым страницам; обновляющий версии скрипт автоматически охватывает `/ru/`. Для публикации достаточно готовых статических файлов: ни Python, ни этап сборки на GitHub Pages не требуются.

## SEO-метаданные и социальные превью

`tools/seo-metadata.json` — отдельные SEO-описания игр на EN/RU и конфигурация социальных изображений: путь, размеры, alt. Это не видимый текст страницы; утверждённые словари не меняются. `tools/generate-localized-pages.py` применяет описания к description, Open Graph, Twitter и JSON-LD. Не правьте эти сгенерированные теги вручную: следующий запуск заменит их.

После изменения конфигурации:

```sh
python3 tools/generate-localized-pages.py
python3 tools/generate-localized-pages.py --check
python3 tools/update-assets-version.py --check
```

Генератор обслуживает пять EN/RU-пар, SEO-головы четырёх общих юридических документов и 404. Тело юридических документов он не меняет. У общих документов нет вымышленных языковых адресов и `og:locale:alternate`; `og:locale=en_US` соответствует английской оболочке страницы. У пар EN/RU выставлены `en_US`/`ru_RU` и соответствующий alternate.

Социальные изображения используют PNG по абсолютным HTTPS URL для совместимости с краулерами:

- Студия и 404: `assets/images/studio/social-preview.png`, 1200 × 630.
- Его редактируемый геометрический исходник: `assets/images/studio/social-preview.svg`. Используется существующая монограмма GS, без внешних изображений.
- First Words и её документы/поддержка: корневой `FeatureImage.png`.
- Words from Word и её документы/поддержка: `assets/images/gramma-words-from-words/FeatureImage.png`.

SVG превью можно растеризовать штатным инструментом macOS, проверив результат и размеры:

```sh
sips -s format png assets/images/studio/social-preview.svg --out /tmp/studio-preview.png
sips -g pixelWidth -g pixelHeight /tmp/studio-preview.png
```

Перед заменой опубликованного PNG просмотрите изображение: растеризация системных шрифтов и итоговый вес могут зависеть от инструмента.

### JSON-LD

На главных — `Organization`, на страницах игр — граф Organization + MobileApplication. Тип MobileApplication выбран для мобильных игр. Идентификаторы организации и приложений одинаковы между EN/RU, но URL, название и описание соответствуют языковой странице. Для First Words `installUrl` берётся из настоящих ссылок магазинов в HTML; для второй игры он не добавляется.

Не добавляйте неподтверждённые ratings, reviews, offers, стоимость, даты выпуска и версии. Разметка помогает описать сущность; без обязательных для Google данных о цене и рейтинге/отзыве расширенный результат приложения не обеспечивается. Юридическим страницам и поддержке JSON-LD не назначается.

Локальная проверка синтаксиса всех JSON-LD стандартным Python:

```sh
python3 - <<'PYCODE'
from pathlib import Path
import json, re
for path in [Path('index.html'), *Path('projects').rglob('*.html'), *Path('ru').rglob('*.html')]:
    for data in re.findall(r'<script type="application/ld\+json" id="site-schema">(.*?)</script>', path.read_text(), re.S):
        json.loads(data)
        print('JSON OK:', path)
PYCODE
```

Это проверяет JSON, а не право на расширенный результат. После публикации дополнительно используйте Schema.org Validator и Google Rich Results Test, сверяя разметку с видимым содержимым.

### Оптимизация изображения второй игры

Оригинальный PNG сохранён: 1024 × 500, 823 876 байт. Добавлен `FeatureImage.webp`: те же размеры, качество 98, 228 470 байт. WebP применяется через `<picture>` в каталоге и Hero; `<img>` сохраняет PNG для браузеров без WebP. Hero имеет `loading="eager"` и `fetchpriority="high"`, карточка каталога — прежний lazy loading. Для OG/Twitter намеренно используется PNG.

Сравнивались WebP quality 95 (184 962 байта), 98 (228 470) и lossless (659 008). Выбран 98 после визуальной проверки полного кадра и текста/рамки. AVIF также рассматривался, но дополнительный вариант в этот этап не включён: основной выигрыш получен высококачественным WebP, без расширения цепочки форматов.

Для повторного кодирования используйте уже доступный конвертер с поддержкой WebP. В этой сессии использован существующий Pillow 13 в локальном окружении Codex — новые пакеты не устанавливались. Генератор сайта от Pillow не зависит. В Python-окружении, где Pillow уже доступен:

```sh
python3 - <<'PYCODE'
from PIL import Image
source = 'assets/images/gramma-words-from-words/FeatureImage.png'
Image.open(source).save(source.replace('.png', '.webp'), quality=98, method=6)
PYCODE
```

Не меняйте размер, не обрезайте и не корректируйте цвета. После кодирования просмотрите обе версии при масштабе 100%: «ГРАММА», подзаголовок, «ЭВРИКА», рамка и дерево. При новом исходнике заново оцените качество и вес, не полагайтесь только на прежнее число quality.
